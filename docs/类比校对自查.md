# 高风险类比自查

- 日期:2026-09-29
- 目的:降低"找懂技术的人校对"的成本。我(AI)先自查最不放心的 5 个类比,标出**潜在误导点**和**更严谨说法**,给最终校对人当检查清单。
- 判定图例:🟢 基本可放心 · 🟡 已收紧,建议复核 · 🔴 有实质误导,已改

---

## 1. 缓存 🟢(已略收紧,可放心)

- **当前类比:** 常点的菜先备好料,来单立刻上;缓存=把常用数据存近处,下次不用跑远路,快但可能是旧的;清缓存=重新拿最新。
- **潜在误导点:**
  1. 让人以为缓存只关乎"数据新旧",其实缓存也可以是**算好的结果、图片、页面**,不只是"数据副本"。
  2. "清缓存"不总能解决问题,只是常见的第一招。
- **更严谨说法:** 缓存 = 把"要重复用、重复算或重复取"的东西,先存一份在更快/更近的地方,省时间。代价是它可能过期,所以有"刷新/清缓存"。
- **结论:** 类比方向正确,beginner 够用。**保留**,可选在卡里加一句"(不只是数据,算好的结果也能缓存)"。

## 2. Token(令牌)🟢(标准类比,可放心)

- **当前类比:** 登录后发的"临时手环",之后亮手环不用反复刷卡;有有效期。
- **潜在误导点:**
  1. 手环"证明我登录过"——更准确说,**手环本身就是通行凭证**,谁拿到都能用(所以 Token 被偷=账号被盗)。
  2. 没点出"有效期到了要重新登录"。
- **更严谨说法:** Token = 登录后系统发给你的一串"通行凭证",之后每次请求带上它就免再输密码;它会过期,也不能泄露(被别人拿到等于被冒用)。
- **结论:** 业界通用类比,**保留**。若要更稳,可在追评/进阶层补"手环别给别人看"。

## 3. 云 / 云服务 🔴→🟡(已改)

- **原类比问题:** 把"云"几乎等同于"存文件到别人服务器",**过窄**。云还包括租算力、跑程序、数据库等(云计算 ≠ 云存储)。
- **已改为:** "按需租别人现成的**算力和存储**;存文件、跑程序都能放到云上;用多少付多少。"卡里 praise 也加了"(存文件只是云的用途之一)"。
- **仍需复核:** "别人的服务器"可能让人误以为不安全/不归自己管;严格说云也有"私有云"。beginner 层可不展开。
- **结论:** 已收紧,🟡 建议校对人确认措辞。

## 4. 系统 🔴→🟡(已改)

- **原类比问题:** 把"系统"和"操作系统"**混为一谈**。日常开发里"系统"常指"整套软件/后台系统",而 iOS/安卓是**操作系统**,是两个层级。原文一句话滑过去,容易糊。
- **已改为:** 明确分层——"系统"是个大词(餐厅运转、公司后台系统都算);手机里管它运转的那一套**专门叫操作系统**(iOS/安卓)。praise 补"操作系统是系统里最基础的那一层"。
- **结论:** 已把两层拆清,🟡 建议校对人确认对 beginner 是否够清楚、会不会反而信息过载。

## 5. 联调 🟢(可放心)

- **当前类比:** 服务员和后厨"对暗号",前后端一起对接接口、确认能正常通信。
- **潜在误导点:** 联调不止"确认能通",还包括**联合排查对接时冒出的 bug**。略窄但不算错。
- **更严谨说法:** 联调 = 前端和后端把各自做好的部分接到一起跑,验证接口传参/返回一致,并一起解决对接时暴露的问题。
- **结论:** beginner 够用,**保留**,可选补"顺便一起抓对接时的 bug"。
