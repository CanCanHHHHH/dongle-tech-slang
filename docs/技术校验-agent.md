# 技术校验报告（逐词）— 「懂了」技术黑话翻译器

- 事实来源：`index.html` 中的 `LEVELS` 数组（本次以代码为准，未参考 docs 旧摘要）。
- 审查范围：11 关，共 47 个词（Lv.1–Lv.3）。
- 校验日期：2026-09-30。
- 评级口径：
  - ✅ 准确（可放心）
  - 🟡 够用的近似（对小白无害，可选优化）
  - 🔴 有实质错误/误导（必须改）
- 本报告只审查、不改 `index.html`。

## 一、总评级统计

| 评级 | 数量 | 占比 |
|---|---|---|
| ✅ 准确 | 41 | 87% |
| 🟡 近似（建议优化） | 6 | 13% |
| 🔴 实质错误/误导 | 0 | 0% |
| 合计 | 47 | 100% |

结论：整体质量高，类比自洽、正确答案与错误项 `why` 大多站得住。无必须改的硬错误；6 个词有可优化的小瑕疵，其中「鉴权/权限」「并发」「客户端」最值得打磨。

高风险词专项复核（系统、云、缓存、Token、联调、Webhook、灰度 vs A/B、并发、索引、埋点、日志、401/404/500）：绝大多数处理得很好——尤其「缓存」点明了「可能是旧的」、「A/B 测试」错误项直接把它和「灰度」区分开、「灰度」错误项把它和「测试环境」区分开、「系统」明确区分了「系统」与「操作系统」。仅「并发」「状态码(500)」有措辞级小瑕疵。

## 三、给主会话的改法优先级

1. 【最值得改】鉴权 / 权限：改标题为「权限/授权」，正文区分 认证(401) vs 授权(403)，少用「鉴权」。
2. 【建议改】并发：plain 从「多少人一起用」改为「多少请求一起涌进来」。
3. 【建议改】客户端：plain 把「设备」改为「App/软件端」。
4. 【可选】状态码 500 措辞、域名/网址补一句 URL、第三方/SDK 补一句 API 路径。

（以上均为措辞级优化；无阻断性错误，不改也不会误导到「讲错」的程度。）
